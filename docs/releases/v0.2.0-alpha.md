# SilkMC v0.2.0-alpha

SilkMC v0.2.0-alpha rebases the project onto Minecraft **26.2**, moving up from the
previous 26.1.2 baseline. All compatibility infrastructure from the v0.1.x line
(compatibility policy, per-plugin overrides, the `/silkmc` operator command, and the
scheduler bridge) is preserved.

## Highlights

- Upstream baseline moved from Folia `26.1.2` to Folia `26.2` (`ver/26.2.x`).
- Paper base bumped to `2717585e686d7d294cabce9f1753280780ecf847`.
- All maintained region-threading patches regenerated against the 26.2 sources.
- Locator-bar / region-threading waypoint support carried forward and fixed for 26.2.
- Two 26.2 API-break fixes applied to SilkMC code (see below).

## Minecraft 26.2 update

- `mcVersion` and `apiVersion` are now `26.2`.
- Folia's regenerated `26.2` region-threading base and feature patches were adopted
  wholesale where SilkMC tracked them unchanged (`0001`–`0008` minecraft feature
  patches, the server/api `build.gradle.kts` and TPS/watchdog/build paper patches).
- SilkMC-only patches were rebased onto the new base:
  - `0009 Restore locator bar and region threading fixes` (minecraft feature patch)
  - `0008 SilkMC compatibility improvements` / `0009 SilkMC operator command`
    (paper patches).

## Bug fixes for 26.2 API changes

- **Region status MSPT read-out**: `SilkPluginCompatibilityManager` referenced
  `ca.spottedleaf.moonrise.common.time.TickData`, which no longer exists after the
  26.2 leafpile repackaging. Updated to `ca.spottedleaf.common.time.TickData` so
  `/silkmc status` and the status line continue to report worst-region MSPT.
- **Waypoint distance scheduling**: `RegionThreadingWaypointManager` accessed the now
  `protected` `Entity.random` field directly, which fails to compile on 26.2. Switched
  to the public `Entity#getRandom()` accessor.
- **Respawn-anchor charge on cross-region respawn**: the carried-forward respawn-anchor
  charge consumption is now routed through `moonrise$loadChunksAsync` so the charge is
  consumed on the owning region thread after the respawn completes.
- **Legacy sync teleport bridge**: `CraftPlayer#teleport0` no longer leaves unreachable
  upstream teleport code after the compatibility bridge returns.
