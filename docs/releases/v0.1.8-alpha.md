# SilkMC v0.1.8-alpha

SilkMC v0.1.8-alpha is a bugfix release that corrects client command-tree synchronization so valid commands stop rendering as red/unknown.

## Highlights

- Fix `/help`, `/pl`, and other commands appearing red/unknown in the client even though they still executed server-side. `Commands.sendCommands` synchronized the client's command tree via a 1-tick delayed entity task (`taskScheduler.schedule(..., null, 1L)`). Under Folia region threading that delay could run *after* the client had already processed the join/command packets, leaving the client's command tree unsynchronized. The sync now uses the guaranteed immediate/queued `taskScheduler.scheduleOrExecute(...)` path, which runs inline when already on the owning region thread or enqueues onto it otherwise, with no artificial delay.

## Notes

- No command behavior changed server-side; only the timing of client command-tree synchronization was affected. Commands that previously rendered red already executed correctly — they now render as valid.
- The new pattern matches how the rest of the region-threading base patch schedules per-entity work.
- Region-threading, locator-bar, and plugin-compatibility behavior from prior releases are unaffected.
